6. Key Takeaways

  1. Real-world overhead < 5% — HTTP integration benchmark confirms guardrail overhead is +0.6ms to +1.4ms, single-digit percentage of total latency. With real model inference this drops to < 1%.
  2. Zero leakage — All 12 cross-chunk boundary tests pass with 0 leakage bytes. Holdback + window scanning design is effective.
  3. PII scanner dominates cost — sensitive scanner accounts for ~85% of S2 unit-level processing time. Consider caching compiled patterns or a faster PII engine for high-throughput deployments.
  4. Secrets scanner is an outlier — secrets costs ~372ms per request (135× more than ban_substrings) due to detect-secrets library overhead. Avoid in streaming hot paths; use as a post-processing step.
  5. Other scanners are 2.7–11.6ms — All 8 scanner types now benchmarked. The remaining 6 (json, invisible_text, reading_time, regex, token_limit) are in the mid-tier range.
  6. Chunk size matters — At 20 chars/chunk (typical vLLM output), S2 unit-level cost is ~24ms. Larger chunks reduce overhead significantly.
  7. Holdback is cheap — Default 256-char holdback adds only ~0.2ms TTFT delay. Can increase to 1024 for better cross-chunk safety at < 0.5ms additional cost.
  8. Policy reload is fast — Sub-2ms P50, atomic swap, zero request disruption.
  9. Non-streaming is very cheap — NS1 adds only ~1ms total (single-pass scan vs per-chunk streaming scan).
